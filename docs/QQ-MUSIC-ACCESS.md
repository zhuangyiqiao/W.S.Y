## 建议申请步骤

1. 以应用所有者身份登录官方平台，点击“开始接入”。
2. 提交真实主体资料、应用名称“life.ing｜生活进行时”、图标、网站用途、计划域名和演示页面。若个人身份无法提交，先向平台咨询是否接受个人/非商业项目及对应渠道。
3. 明确申请的是“用户授权自己的 QQ 音乐账号，在第三方浏览器网页读取个人歌单并播放”，而非普通 QQ 登录或控制手机 QQ 音乐 App。
4. 同时确认 H5 授权、个人歌单读取、浏览器内播放、播放权益、上一首/下一首/暂停/进度/音量、可公开使用范围、调用额度与计费。
5. 获批后配置 HTTPS 回调域名，把 appkey 等密钥放在服务端 secrets；不能写入前端或 GitHub。
6. 用正式测试账号验证完整授权、Token 换取/刷新/撤销、歌单、可播放/不可播放歌曲，再开放站内控制。

## 接入目标与当前边界

正式验收必须是：**官方授权 → 返回本站 → 选择个人歌曲/歌单 → 左侧实际播放、暂停、切歌和调音量**。打开外部 QQ 音乐页面不算完成。

目前新增了左侧控制布局、音乐会话接口边界与权限门控：

- `GET /api/music/qq/status` 明确返回未开通、未授权、无播放权限。
- 授权、播放、暂停、上下首、进度和音量入口仅在实际适配器声明已开通/已授权/可播放及支持相应操作后才可启用。
- 当前 `/api/music/qq/authorize` 与播放命令返回明确的服务未开通错误；没有伪造成功回调或占用演示 appid。
- `assets/js/music-session.js` 目前是前端交互契约与门控，不是已完成的 QQ 官方播放器。获批后还需实现服务端令牌处理、官方播放适配器及真实音频/SDK事件，不能只把状态改成 true。
- 外链功能收在“关于音乐连接”中作为临时回退，不推断平台登录状态，也不冒充本站授权。

## 授权后的实现安排

1. 同源后端生成一次性 state，记录短期 HttpOnly 会话，将用户导向平台核准的授权入口。
2. 回调先验证 state、来源与一次性使用，再由后端按官方协议换取令牌。令牌加密保存，前端只获状态和必要的播放参数。
3. 读取允许的个人歌单；播放通过平台批准的浏览器方案落到左侧控制器，界面显示真实播放事件和进度。
4. 分别处理授权成功但无播放权益、拒绝/取消、令牌过期、歌曲不可播、断开连接。环境音混音不依赖音乐连接。
5. 房间只共享被允许的歌单项与当前歌曲标识，不共享个人 Token 或强制广播音频流。

如果平台不批准浏览器场景，应明确标记该目标不可交付；更换服务器或从 GitHub Pages 搬家不会自动获得音乐版权或平台权限。
