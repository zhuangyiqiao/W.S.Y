# 静态发布与维护

本次发布只需要 GitHub Pages：无运行时 API、数据库或云端密钥。

可用功能：四场景原创 SVG、开放许可录音混音、音量与静音、QQ 歌曲/歌单链接收藏、待办、番茄钟、四只猫、夜间配色、本机专注统计。本地数据仅存在当前浏览器，清除网站数据会丢失记录。

音乐仅通过外链在 QQ 音乐收听；没有站内音乐授权与播放控制。账号、云同步、多人房间不在本次发布范围内。各场景按真实录音选配：咖啡馆三轨、雨夜一轨、海边一轨、篝火两轨。未取得合适录音的占位音轨已下架。

2026-10-31 本地优化：以上音轨数量为场景推荐列表；“全部声音”可自由混合六条录音，并支持恢复混音及切场景保留组合。手机采用音乐/环境音面板切换；场景和猫咪支持淡化及计时状态反馈。闲置解码缓存使用 24MiB 回收预算，活动音轨可超出此预算。发布前检查结果见 [第六天验收](DAY-6-VALIDATION.md)，本段不代表已部署到线上。

## 开发与验证

Node.js 22.17+；不需要安装依赖。执行 `npm run dev` 预览，`npm run check` 检查代码，`npm test` 检查计时、存储迁移、链接安全、录音完整性及循环/取消行为，`npm run build` 生成 `public/`。

## 发布

推送 `main` 后 `.github/workflows/deploy-pages.yml` 自动检查、构建并部署 `public/`。仓库 Settings → Pages 的 Source 应为 GitHub Actions。源码、测试和维护文档不进入 Pages 产物；仅 HTML、assets 静态文件发布。

不提交 `.dev.vars`、`.env`、`.wrangler/`、原始录音、临时工具或本地云端草稿。音频文件使用相对于 JS 模块的 URL，在 `/W.S.Y/` 子路径也可加载。

## 日常维护

- 增加录音前核实原始作品页许可，补齐 `assets/audio/CREDITS.md`、`manifest.json` 与 `assets/js/sound-catalog.js`，然后运行测试。
- 提交音频前完整解码检查；手机上验证加载、音量、暂停与场景切换。音频按点击加载，同一页面内复用解码缓存，避免首次访问加载全部录音。
- 页面故障先查看 Actions 的 Deploy Pages；音频故障检查网络请求与 manifest 哈希，保留原始作者署名。
- 回滚通过新提交撤销问题提交后重新部署，不强制推送历史。
- 暂不承诺跨设备同步；未来接后端时再迁移数据与开启对应入口。
